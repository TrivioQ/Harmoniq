# Terraform provider for Harmoniq

Manages [Harmoniq](https://github.com/TrivioQ/Harmoniq) as code (IaC-01..04). It covers workspaces, host apps, environments with approval policies, remote modules, API keys, webhook endpoints and alert rules. Instance operators can also manage instance settings and tenant plans. Data sources read workspaces, environments and manifests. Built with `terraform-plugin-framework`.

```hcl
terraform {
  required_providers {
    harmoniq = { source = "harmoniq-dev/harmoniq" }
  }
}

provider "harmoniq" {} # HARMONIQ_REGISTRY_URL, HARMONIQ_API_KEY

resource "harmoniq_workspace" "checkout_team" {
  organization = "acme"
  slug         = "checkout-team"
  name         = "Checkout team"
}

resource "harmoniq_host_app" "storefront" {
  workspace = harmoniq_workspace.checkout_team.slug
  slug      = "storefront"
  name      = "Storefront"
}

resource "harmoniq_environment" "production" {
  workspace = harmoniq_workspace.checkout_team.slug
  host_app  = harmoniq_host_app.storefront.slug
  slug      = "production"
  name      = "Production"
  approval_policy = {
    required_approvers = 2
    eligible_roles     = ["admin", "owner"]
  }
}
```

Reference: [`docs/`](docs/index.md) (generated by `tfplugindocs` from the schemas and [`examples/`](examples/)).

## Credentials

Use an **organization API key with the `admin` scope**, not limited to some workspaces (Organization → API keys). It can create and delete the organization's workspaces and issue workspace API keys. A workspace key with the `admin` scope can manage what's inside its workspace, but not workspaces or API keys.

Instance administration (`harmoniq_instance_setting`, `harmoniq_workspace_plan`, `harmoniq_organization_plan`) needs an **instance API key** (`hq_inst_…`, scope `instance:admin`), created by an instance owner (Admin → API keys). Use a second, aliased provider block for it. Instance keys can't reach tenant APIs. They also can't manage instance admins or keys, so admins aren't managed by Terraform.

## Behaviour worth knowing

- New workspaces come with a `default` host app with `staging` and `production` environments. Import it (`terraform import harmoniq_host_app.default <workspace>/default`) or ignore it.
- Deleting a host app, environment or module is refused while it serves module versions: roll them back first. Versions are deployed by CI (the CLI, GitHub action or GitLab component), not Terraform.
- API key secrets and webhook signing secrets are only known at creation. They are empty after an import.
- `harmoniq_instance_setting` takes the whole setting as JSON. A change made in the admin panel shows as a diff and the next apply restores the Terraform value. Destroying it resets the setting to the environment's defaults.
- Destroying a `harmoniq_workspace_plan` or `harmoniq_organization_plan` puts the tenant back on `hobby` without overrides.
- Use either `harmoniq_environment.approval_policy` or a `harmoniq_approval_policy` resource for an environment, not both.

## Develop

Go 1.25 or later. From this directory:

```bash
go build ./...
go test ./...                                  # unit tests
go generate ./...                              # regenerate docs/ (needs terraform on PATH)

# Acceptance tests: real Terraform against a development registry (HARMONIQ_DEV_LOGIN=1)
eval "$(scripts/acc-env.sh http://localhost:4000)"
TF_ACC=1 go test ./internal/provider -run TestAcc -v
# Instance administration tests also need an instance key: start the registry with
# HARMONIQ_SETUP_TOKEN on a fresh database and export it before acc-env.sh (skipped otherwise).
```

CI runs the unit tests, the acceptance tests against the registry it starts, and a check that `docs/` is up to date.

## Publishing (maintainers)

The Terraform Registry publishes providers from a public GitHub repository named `terraform-provider-harmoniq`, from GitHub releases signed with a GPG key registered with the registry.

1. Copy this directory to the root of `harmoniq-dev/terraform-provider-harmoniq` (with `LICENSE`).
2. Add the GPG public key in the registry (namespace `harmoniq-dev`), and the private key and passphrase as repository secrets.
3. Release a `v*` tag with GoReleaser (`.goreleaser.yml`), e.g. via `goreleaser/goreleaser-action` with `GPG_FINGERPRINT` set. The registry picks up new releases.
